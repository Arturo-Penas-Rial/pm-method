# Verificación · pm-method 2.7.0 · portal unificado de pm-kb

Fecha: 2026-10-30 · Autor del encargo: Arturo Penas Rial ([LinkedIn](https://www.linkedin.com/in/arturopenasrial/)).

**Alcance:** las capacidades del portal unificado según la definición aprobada el 2026-10-29: el tablero en el núcleo
de pm-method (`tablero.py`, `pm-tablero/1`) con instantáneas congeladas en cada puerta; tarjetas-enlace con ids
estables, ubicaciones y movimientos (`pm-kb enlaces`); el portal web (cartera, tableros con historial, comparar, por
actor, artefactos, documentos de skills externas en marco aislado, «actualizar ahora»); los enlaces compartidos
(`pm-kb compartir`); `pm-kb vigilar` como servicio en WSL2 y en Docker; y su interacción con el resto (puertas,
propuestas, BMAD, proyectos en inglés, carpeta de solo lectura, skills externas, los dos entornos).

**Criterio de salida:** el de la versión estable ([PRUEBAS §2.5](../../PRUEBAS.md)): 0 FALLO en dos corridas seguidas de
la suite de variantes, sin trazas, omisiones = manifiesto y evidencia de las guías E2E idéntica entre corridas; además
la regresión, la integración cruzada y la batería de la imagen Docker dos veces.

El detalle de los cambios está en el `CHANGELOG.md` (2.7.0).

## 2. Defectos encontrados durante la verificación y corregidos

| Área | Defecto | Corrección |
|---|---|---|
| pm-kb | Una indexación que coincidía con `pm-kb base crear` reaplicando el esquema podía abortar por interbloqueo (la suite lo provocó con `base crear` repetido mientras otra unidad indexaba) | La aplicación del esquema y la carga de un índice o de un tablero se ordenan con un bloqueo consultivo de PostgreSQL (exclusivo y compartido) y la carga se repite entera ante un interbloqueo |
| Arnés de las guías | Con las cinco guías en paralelo (integración cruzada), E2E-1 y E2E-3 indexaban y quitaban el mismo proyecto en la misma base, y cada `pm-kb servir` revoca la sesión local anterior: las capturas de E2E-1 quedaban sin datos | El tramo de pm-kb de cada guía toma un bloqueo de archivo entre procesos; las capturas esperan más con el equipo cargado |
| pm-kb | El mensaje de `pm-kb compartir crear` decía «al instantánea» | «a la instantánea» |

## 3. Qué no se probó y queda para tu equipo

- **`pm-kb vigilar` como servicio de systemd dentro de WSL** (INSTALACION-WSL2 §8.10): la unidad pasa
  `systemd-analyze verify` y la alternativa sin systemd se probó tal cual en un contenedor, pero no en un WSL real.
- **El portal desde un navegador de Windows** y con HTTPS delante (PM-KB §13): las pantallas se probaron con Chromium en
  Linux.
- **Modelos reales de pm-kb, Hermes completo, Windows nativo, Docker Desktop y arm64**, y los envíos reales: como en
  la estabilización de 2.6.2 (sus guías tienen el paso a paso).
- **Batería en vivo con Claude Code** (`suite.py`): no se repitió; las descripciones de las skills no cambiaron.

## 4. Cómo reproducirlo

```bash
python3 scripts/validar_paquete.py
python3 scripts/probar_paquete.py
python3 scripts/pruebas/integracion/correr.py
python3 scripts/pruebas/variantes/correr.py --nivel todo --repetir 2 --salida /tmp/variantes
python3 pm-kb/pruebas/probar_kb.py && ~/.local/share/pm-kb/venv/bin/python pm-kb/pruebas/probar_kb.py --con-base
python3 pm-kb/pruebas/pantallas.py --salida /tmp/pantallas
docker compose -f docker/compose.yaml run --rm pruebas        # imagen pm-method:2.7.0
```

Los niveles que necesitan PostgreSQL, Docker o las copias de las skills externas se omiten de forma explícita cuando
falta alguno de ellos ([PRUEBAS §2.5](../../PRUEBAS.md)).
